# BB 실사 Visible Mask·데이터 누출·XYZ 규약 검토

작성: 2026-11-08 (KST). 범위는 실사 개발 27장과 BB 실사 GT 100장, 대표 BB 10장, 기존 PBR 5장이다. 기존 원본과 체크포인트는 읽기만 했다. BB 100장 전체 라벨 생성과 GPU 학습은 수행하지 않았다.

## 결론

- 실사 개발 27장과 BB 100장 사이에 **파일 또는 디코딩된 픽셀이 완전히 같은 이미지**는 발견되지 않았다. 하지만 영상 재인코딩·편집·인접 프레임까지 같은 촬영이 아닌지 입증한 것은 아니다. BB 내부에는 완전히 같은 pose가 반복되는 연속 프레임 그룹이 많아 무작위 프레임 분할 시 누출 위험이 높다.
- 대표 10장의 CAD 마스크는 보이는 물체의 정답이 아니라 다른 물체의 가림을 무시한 투영이다. 가려진 075, 099, 221, 235, 340번은 그리퍼가 차지하는 영역을 물체 전경으로 포함한다. 031, 043 등 가림이 적은 영상에서도 미세한 경계·구멍 불일치가 보인다. 실제 visible mask 정답은 없어 이 차이의 IoU나 가림률은 산출할 수 없다.
- 기존 PBR 다섯 프레임에서 같은 CPU 방식으로 계산한 Front/Back 라벨 10개가 저장된 PBR 라벨과 OpenCV 배열 기준 완전히 일치했다. 이는 기존 **CPU 생성 PBR 라벨과의 동등성**이다. 원본 VisPy 렌더러와의 비트 단위 동등성은 미검증이다.

## 1. 27장과 BB 100장의 중복·촬영 구간

27장 각각의 원본 JPEG 및 기존 보정 JPEG, BB 100장의 보정 JPEG를 SHA-256으로 검사하고, 디코딩된 전체 픽셀 배열도 해시 비교했다. 구분별 27×100 파일 쌍에서 동일 파일은 0쌍이고, 디코딩 픽셀이 완전히 같은 쌍도 0쌍이다. 보정 방식과 JPEG 인코딩이 다르면 같은 원 영상이라도 해시가 달라질 수 있다. BB raw 원본은 이 실험 폴더에 없어 raw-to-raw 대조는 하지 못했다. 목록: [image_hashes.csv](image_hashes.csv).

보정 영상 27×100 쌍에 대해 160×90 BGR 축소 이미지의 평균 절대 차이(MAE), 회전 상대각 `acos((trace(R_old R_bb^T)-1)/2)`, translation 유클리드 거리를 계산했다. [전체 2,700쌍](all_2700_pairs.csv), [기존 프레임별 각 기준 최근접 쌍](nearest_pairs.csv). 영상 MAE는 배경·조명과 보정에 민감하고 같은 장면 판별의 검증된 임계값이 아니다. pose는 제공된 값의 비교이며 대칭이나 라벨 오차를 보정하지 않았다.

프레임 번호가 같은 32, 38, 83, 99번도 이미지 파일 해시가 다르며 각각 상대 회전 25.51°, 28.61°, 27.90°, 30.77°, translation 거리 61.78, 82.53, 74.08, 79.92 CAD 좌표 단위다. 따라서 번호 일치만으로 같은 프레임이라고 볼 수 없다. 가장 작은 영상 MAE는 기존 83번–BB 101번의 22.63/255이며, 그 쌍의 pose 차이는 26.63° 및 25.24 단위다. 가장 작은 translation 거리는 기존 83번–BB 97번의 8.62 단위이고 상대 회전은 26.80°다. 수치가 작다는 사실만으로 동일 영상 또는 독립 영상임을 판정할 수 없다.

BB 저장 이력의 스크립트 기본 입력 경로는 `BB_rgb/.../run_20260813_164421/rgb_undistorted`이며 디렉터리 상태명은 FEEDING·READY·APPROACHING·PICKING·TRANSPORTING·RETURNING 등이다. 이는 파일에 남은 경로·상태 정보이지 촬영 timestamp나 전체 주기 경계의 검증은 아니다. 기존 27장에는 촬영 구간 매니페스트가 확인되지 않아 두 세트가 서로 다른 촬영 세션인지 확정하지 못했다.

BB GT에서는 동일 숫자의 R,t가 반복되는 그룹이 확인된다. 예를 들어 235–278 사이 17장(실제 ID는 235,237,239,241,243,245,247,249,251,253,255,257,259,261,263,272,278), 373–419 사이 10장, 44–74 사이 9장이다. 43과 60도 동일하며 스크립트에는 60이 43의 pose 복사라는 이력이 있다. 동일 pose가 독립 pose 검증을 의미하지는 않는다. **분할 전 원본 run·시간·로봇 주기 기록을 확보하고, 동일 촬영 주기 및 가까운 시간·pose 그룹을 묶어서 분리**한다. 기존 27장은 개발용으로 취급하고, 두 세트의 출처가 확인되기 전에는 독립 최종 테스트로 주장하지 않는다. 분할 후 유사도·시간 버퍼와 누출 여부를 다시 검사한다.

## 2. 대표 10장과 실제 visible mask의 차이

기존 전체 접촉 시트를 훑어 가림 및 로봇 상태가 다른 표본을 선정하고 각 원본 해상도에서 투영했다. 분류는 RGB를 보고 판단한 **정성적** 구분이며 측정된 가림률이 아니다. 각 링크는 왼쪽 RGB, 가운데 CAD 초록색 반투명 투영과 노란 외곽, 오른쪽 이진 amodal pseudo mask를 보여준다. 모두 같은 물체 주변 crop이다.

## 3. Visible Mask 제작 방안

| 방법 | 장점 | 한계 및 검수 |
|---|---|---|
| CAD 마스크 초기값 + 수동 브러시/폴리곤 보정 | 100장 규모에 적용 가능; 외곽·구멍과 가림 영역을 직접 판단 가능 | 작업자 시간과 주관성, 어두운 경계의 불확실성. 원본 RGB 위에서 확대하고 독립 검수 필요 |
| CAD 초기값 + 대화형 분할 보조(전경/배경 클릭·붓질) | 반복 영역 보정 속도를 높일 가능성 | 얇은 판·구멍·접촉부에서 오류 가능; 도구/모델의 사용 가능 여부 및 정확도는 이번에 검증하지 않음. 프레임별 수동 승인 필요 |
| 인접 프레임으로 마스크 전파 후 보정 | 연속 영상에서는 반복 작업을 줄일 수 있음 | 그리퍼 접촉·이동·가림 변화에 오류가 전파되므로 독립 검수 필요; 누출 없는 분할 후 분할 간 전파 금지 |
| CAD 마스크 그대로 사용 | 가장 빠르고 가림 없는 근사 참고자료 | 가려진 그리퍼를 전경으로 오인하고 pose 오차도 남으므로 visible GT로 부적합 |

권장 절차: (1) 위 10장에 대해 두 사람이 독립적으로 visible mask를 작성하고 불일치를 조정한 기준셋을 만든다. (2) CAD 초기 마스크를 사용해 그리퍼·호스·배경을 제거하고 물체 외곽과 구멍을 보정한다. (3) 조명, 가림, 얇은 테두리가 모호한 픽셀은 별도 uncertainty 마스크로 기록하고 학습 시 무시하는 처리가 구현·검증될 때만 사용한다. (4) 보조 방식은 이 독립 기준과 IoU 및 경계 오차, 가림별 실패율을 비교해 수용 기준을 정한 뒤 적용한다. 필요하다면 검수한 visible mask와 CAD full mask 간 차이를 정량화한다. (5) 마스크와 CAD/XYZ 유효 영역이 어긋나는 픽셀을 검출해 pose를 재검토하고, 단순 교집합으로 숨기지 않는다. bbox_visib와 scene_gt_info는 검수 완료된 mask에서 계산한다.

## 4. Front/Back XYZ와 PBR 라벨 규약

기존 CPU 렌더러는 양면 삼각형의 카메라 깊이 최소/최대를 front/back으로 사용하고, 픽셀 중심 +0.5에서 렌더링한다. 원본 구현과 같이 **정수 픽셀 좌표**를 사용해 깊이를 역투영하고 `(X_camera-t)R`로 모델 좌표를 얻는다. `models_info`의 축별 min/size로 정규화해 [0,1]로 클리핑하고 255배 반올림한 uint8의 배열 채널 0/1/2에 X/Y/Z를 넣어 `cv2.imwrite`한다. 읽을 때도 `cv2.imread`의 채널 0/1/2가 X/Y/Z다. 일반 RGB 뷰어로 PNG를 열 때 보이는 색 순서를 XYZ라고 가정하면 안 된다. 원본 로더는 별도 `mask_visib`와 `bbox_visib`를 사용하며, 좌표가 0인 값은 유효한 좌표일 수도 있어 별도 유효 마스크가 필요하다. 객체 4의 models_info에는 대칭 항목이 없다.

PBR 프레임 0, 10, 40, 70, 99에서 새 계산과 기존 Front/Back 저장 PNG를 `cv2.imread` 배열로 비교한 결과 **10/10 완전 일치**, 차이 채널 수와 최대값은 모두 0이다. 이 5장의 PBR 기존 전체 객체 mask와 CPU 투영 mask IoU는 0.9868–0.9908이다. 각 10개 독립 ray 교차의 near/far 최대 깊이 차이는 최대 2.19e-11 CAD 단위다. 수치 및 비교 상세는 [pbr_xyz_comparison.json](pbr_xyz_comparison.json). 기존 100장 검증 기록은 [labels_v2_100.json](/RESEARCH_DATA/HCCEPose_experiments/obj04_seminar_v1/checks/labels_v2_100.json)에 있으며, 이번 검사는 그중 다섯 장을 독립적으로 다시 계산한 것이다.

BB 대표 10장의 front ≤ back을 확인했고, 양자화해 복원한 좌표의 재투영 오차 p99는 front 0.358–0.403 px, back 0.364–0.485 px다. 정규화 최대 클리핑 초과는 약 0.00435다. [프레임별 수치](representative_render_metrics.csv). 이는 렌더·역투영·양자화의 자기 일관성이며 실제 pose 정확도나 가림 없는 visible mask를 증명하지 않는다. 기존 PBR 라벨도 같은 CPU 구현에서 생성되었으므로 픽셀 일치는 독립 렌더러 검증이 아니다. 기존 원본 VisPy와 경계·깊이의 픽셀별 차이는 별도 환경에서 검증해야 한다.

## 재현 및 다음 단계

[audit.py](audit.py)는 이 보고서 디렉터리에만 신규 파일을 쓰도록 작성됐으며, 입력 경로는 읽기 전용으로 사용한다. 출력 충돌을 막기 위해 기존 결과 폴더·파일이 있으면 재실행이 실패하므로 재현 시 스크립트를 새 빈 실험 디렉터리에 복사해 실행한다. 기존 PBR 라벨을 생성하는 `generate()`는 호출하지 않고 `mesh()`, `render()`, `independent_rays()`만 사용했다. 다음 단계는 대표 10장에 대한 독립 마스크 주석·합의와 원본 촬영 run/시간 출처 확인이다. 이 단계가 완료되기 전에는 100장 변환과 혼합 학습에 착수하지 않는다.
