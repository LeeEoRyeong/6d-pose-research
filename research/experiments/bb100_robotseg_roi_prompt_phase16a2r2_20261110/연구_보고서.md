# Phase 16A-2R-2 — RobotSeg ROI 및 Guided Prompt

## 판단: CONDITIONAL

**ROI와 수동 점 프롬프트를 함께 쓴 D 조건에서 075와 235의 흰 그리퍼 접촉부 일부가 예측에 포함됐다.** 075는 ROI만 적용한 B 조건에서도 접촉부가 나타났지만, 235는 ROI만 적용하거나 전체 이미지에 점을 준 경우에도 놓쳤다. D의 235번 출력에는 BB 검은 표면과 경계로 보이는 부분도 포함돼 과삭제 가능성이 있다. 따라서 접촉부 분할의 가능성은 보였으나 정확한 visible mask나 실제 수동 수정 시간 단축은 입증되지 않았다. 두 프레임과 수동 지정 점에 근거한 탐색 결과이므로 **100장 자동 적용 및 GT 승인 NO-GO**다.

권고: 현재 주 경로는 **SAM2/CAD 후보의 수동 보정**으로 두고, RobotSeg ROI+점은 사람이 접촉부 보조 후보로 확인하는 소규모 실험만 계속한다. 독립 참조 마스크와 수정 시간 측정 전에는 RobotSeg가 실제 작업량을 줄인다고 주장하지 않는다.

## 공식 API 및 입력 규약

기존 고정 공식 소스 `robotseg/robotseg_video_predictor.py`를 직접 확인했다.

- `add_new_robot(..., robot='gripper')`: 수동 점 없이 범주 프롬프트.
- `add_new_points_or_box(..., robots='gripper', points=..., labels=..., box=...)`: Point 및 Box 지원. labels 1은 양성, 0은 음성이다. 이번 실험은 point 양성 1개·음성 1개를 사용했고 box는 API만 확인하고 추론에 적용하지 않았다.
- `add_new_mask(..., mask=...)`: mask prompt 지원. 이번 실험에서는 사용하지 않았다.
- JPEG 입력을 RGB로 읽고 1024×1024로 리사이즈·정규화한다. `normalize_coords=True`일 때 프롬프트는 입력 이미지 너비·높이로 정규화되어 1024 모델 공간에 전달된다. 출력 logit은 해당 입력 프레임 해상도로 복원된다.

조건 A/B는 `add_new_robot`, C/D는 새로운 독립 inference state에서 `add_new_points_or_box(robots='gripper')`를 사용했다. 앞선 자동 결과의 logit을 이어받지 않았다. 공식 소스·체크포인트를 그대로 쓰고 `apply_postprocessing=False`, raw logit >0을 사용해 이전 실험과 맞췄다. guided refinement·video propagation은 사용하지 않았다. C/D는 RobotSeg 자체 결과이며 별도 SAM2 모델의 guided 결과가 아니다.

## 기준선 및 ROI

사용자 제공 `robotseg.pt`의 SHA-256은 이전과 동일 `1384c38c4f313487a32503025d4566ac1d815f6be983199362fc4af19aaa06a2`, 앞선 공식 구조 strict 로드 검증을 재사용했다. 전체 이미지 A의 결과는 이전 마스크와 **픽셀 단위 동일**했다: 075는 4,440px, 235는 309px, 두 장 모두 기존 SAM과 교집합 0px.

| 프레임 | 추론 ROI `(x0,y0,x1,y1)` 반열림 | 크기 | 수동 양성점 `(x,y)` | 수동 음성점 `(x,y)` |
|---:|---|---:|---|---|
| 075 | (220,0,700,430) | 480×430 | (465,295) | (505,330) |
| 235 | (390,0,890,540) | 500×540 | (640,385) | (690,425) |

ROI는 CAD 투영 전체와 그림에서 보이는 흰 접촉부를 포함하며, 두 점은 영상을 사람이 살펴 접촉부와 BB 검은 표면에 각각 지정했다. **프레임당 사람의 2점 입력이 필요**했다. CAD support와 점의 ROI 포함은 자동 검사했다. 연결 호스와 장치 전체가 ROI 경계를 넘을 수 있고 물리적 그리퍼 전체 범위에 대한 GT는 없으므로, ROI가 전체 그리퍼를 자르지 않았는지는 독립적으로 확증하지 못했다. 본 결과는 접촉부 중심의 조건부 검토다. 호스를 포함한 전체 그리퍼가 평가 대상이라면 ROI 완전성 조건을 충족한다고 볼 수 없어 해당 전체 그리퍼 실험은 무효다.

crop은 기존 JPEG 원본을 읽어 별도 디렉터리에 JPEG quality 100으로 저장한 뒤 공식 JPEG loader로 입력했다. crop과 전체 이미지는 resize뿐 아니라 JPEG 재인코딩 차이도 있으므로 차이를 순수 crop 효과로만 인과 해석할 수 없다. crop의 출력은 원본 좌표 `(x0,y0)`에 오프셋 복원하고 ROI 밖은 미추론으로 둔다. ROI 밖 0은 실제 배경 판정이 아니다.

## 4개 조건 결과

숫자는 예측 전경 및 기존 SAM 후보와 겹쳐 제거되는 픽셀 수다. **정답·정밀도·개선량이 아니다.**

| 프레임 | 조건 | 그리퍼 후보 px | SAM에서 제거 px | CAD∩SAM에서 제거 px |
|---:|---|---:|---:|---:|
| 075 | A 전체 자동 | 4,440 | 0 | 0 |
| 075 | B ROI 자동 | 9,159 | 494 | 434 |
| 075 | C 전체 + 점 | 12,774 | 198 | 164 |
| 075 | D ROI + 점 | 8,907 | 207 | 151 |
| 235 | A 전체 자동 | 309 | 0 | 0 |
| 235 | B ROI 자동 | 292 | 0 | 0 |
| 235 | C 전체 + 점 | 286 | 0 | 0 |
| 235 | D ROI + 점 | 15,152 | 670 | 655 |

075의 B와 D는 접촉부가 빨간 그리퍼 후보에 들어온다. C도 접촉부 일부를 포함하지만 위쪽 장치가 넓게 선택되는 양상이 보인다. 235의 D는 접촉부를 포함하지만 검은 BB 표면의 선 주변도 후보에 포함하는 것으로 보이며, 제거 이미지에서 실제 BB 표면 과삭제 위험을 확인해야 한다. 235의 C는 제공한 **양성점 자체가 이진 출력에 포함되지 않았다**. 점 프롬프트가 hard constraint처럼 항상 지켜진다고 가정할 수 없다. 다른 세 guided 출력은 양성점을 포함했고, 네 guided 출력 모두 지정 음성점은 포함하지 않았다. 단일 점 준수 여부는 전체 segmentation 정확도를 보증하지 않는다.

기존 SAM은 일부 구멍을 채우는 것으로 Phase 16A-1에서 확인됐다. 그리퍼 차감만으로 구멍 복원과 정확한 외곽선이 보장되지 않는다. 모든 A–D 마스크 및 `SAM−mask`, `CAD∩SAM−mask`는 `masks/`에 원본 1280×720 PNG로 저장했다. 사람의 참조 GT가 없으므로 IoU·Dice는 계산하지 않았다.

## 검수 및 테스트

[오프라인 검수 ZIP](BB100_RobotSeg_ROI_guided_review.zip)을 통째로 압축 해제하고 `index.html`을 열면 전체 ROI/점, 접촉부 확대, 4조건 overlay 및 제거 부분을 볼 수 있다. 녹색 십자는 양성점, 빨간 십자는 음성점이며 빨간 overlay는 그리퍼 후보이다. PNG 및 이미지 모두 미검수·비GT다.

8개 조건의 mask 크기·이진 형식, baseline 동일성, ROI 밖 마스크 0, 좌표 오프셋 및 후보 교집합 면적을 검사했다. `results_with_prompt_checks.csv`는 각 guided mask의 양·음성점 포함 여부를 함께 기록한다. Linux headless Firefox에서 2개 카드·6개 이미지·8개 링크를 확인했고 ZIP CRC와 이미지 경로가 일치했다. Windows Chrome 실기기에서는 시험하지 않았다.

두 번 모두 GPU compute 작업이 없음을 확인하고 RTX 5090을 이용했다. PyTorch peak allocated 612,336,128 bytes, reserved 710,934,528 bytes다. 체크포인트, 사용된 RGB·CAD·SAM·기존 RobotSeg 마스크 해시는 실행 전후 동일했다. 기존 데이터와 연구 결과는 수정하지 않았고 추가 checkpoint 다운로드나 학습은 수행하지 않았다.

## 다음 검증

사람이 수정한 독립 visible/gripper 참조 마스크와 여러 Pose·가림 조건에서 그리퍼 누락과 BB 과삭제, 구멍·외곽 품질을 비교하고 직접 수정 시간을 기록해야 한다. ROI의 물리적 그리퍼 전체 포함 여부도 먼저 확인한다. 학습/검증 배치 분리, 대칭 HCCE 타깃과 기존 학습 파이프라인 BLOCKED 판정은 유지한다.
