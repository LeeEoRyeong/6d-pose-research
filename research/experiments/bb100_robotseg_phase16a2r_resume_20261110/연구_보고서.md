# Phase 16A-2R — RobotSeg 체크포인트 재개 실험

## 결과와 판단

사용자가 제공한 RobotSeg checkpoint는 공식 공개 아키텍처와 **strict 로드에 성공**했고 RTX 5090에서 부분 가림 BB 6장 추론이 실행됐다. 그러나 이번 **자동 `gripper` 프롬프트·단일 프레임·raw logit** 조건에서는 물체 접촉부의 흰 그리퍼를 안정적으로 분리하지 못했다. 여섯 장 모두 RobotSeg 마스크와 기존 SAM 후보가 겹치는 픽셀은 0이므로 `SAM−RobotSeg`는 기존 SAM과 완전히 동일하다. `CAD∩SAM−RobotSeg`도 여섯 장 모두 기존 CAD∩SAM과 동일하다. 따라서 이 설정으로 기존 visible mask 후보가 개선됐다고 볼 근거가 없으며, **100장 자동 처리 및 학습용 GT로 사용은 NO-GO**다.

이는 특정 단일 프레임 자동 프롬프트 설정의 결과다. RobotSeg의 클릭·박스 프롬프트, 영상 추적, 후처리를 포함한 모든 사용 방식이 실패한다는 뜻은 아니다. 독립 픽셀 GT가 없어 IoU/정확도는 계산하지 않았다.

## 체크포인트 및 환경

- 입력: `/home/oylee/projects/HCCEPose/robotseg.pt`, 165,436,221 bytes, SHA-256 `1384c38c4f313487a32503025d4566ac1d815f6be983199362fc4af19aaa06a2`. 사용자가 제공한 후보이며 공식 배포본의 공개 해시와 비교하지 못했으므로 파일 출처를 암호학적으로 인증한 것은 아니다.
- `torch.load(..., map_location='cpu', weights_only=True)`로 로드했다. 최상위 `model`, 텐서 585개. 공식 RobotSeg commit `dafb8c0d507276e2f96d2b07ac3661a7b3a41a5f`의 소스·추론 config로 만든 video predictor와 모델 키 585개, 누락 0, 초과 0, shape 불일치 0, `load_state_dict(strict=True)` PASS. [strict_check.json](strict_check.json).
- 공식 저장소의 필요한 Python/YAML 약 311KB만 새 디렉터리에 받았다. 별도 가상환경에서 기존 PyTorch 2.8.0+cu128, torchvision, Hydra 등을 경로 참조하고 Kornia 0.8.1 및 kornia_rs 0.1.15만 별도 설치했다. 기존 환경을 변경하지 않았지만 `.pth` 경로를 통한 기존 패키지 참조이므로 완전히 독립 복제된 환경은 아니다. Kornia Canny 분기 사용을 확인했다.
- NVIDIA RTX 5090에서 다른 GPU compute 프로세스가 없음을 시작 전 확인했다. 235번 smoke test 성공 후 075, 099, 221, 340, 359번을 실행했다. PyTorch peak allocated 612,336,128 bytes, reserved 710,934,528 bytes. 드라이버와 다른 라이브러리 전체 GPU 메모리 사용량과는 다르다. HCCEPose 학습은 실행하지 않았다.

## 추론 조건

공식 `build_robotseg_video_predictor(..., apply_postprocessing=False)`로 모델을 strict 로드하고, 원본 1280×720 JPEG를 바이트 동일한 1장짜리 임시 입력 디렉터리에 복사한 뒤 `add_new_robot(frame_idx=0, robot='gripper')`를 사용했다. 반환한 원본 해상도 logits >0을 마스크로 저장했다. **연속 영상 propagation 없음**, 자동 클릭/박스 없음. 원본 데모의 guided refinement와 동적 multimask 후처리, CUDA 연결 성분 확장 기능은 적용하지 않았다. 원본 데모와 같은 최종 후처리 결과라고 주장하지 않는다. 모든 예측은 `NOT_GT`다.

기존 A=SAM2 후보, B=CAD∩SAM2를 읽어 C=A−RobotSeg, D=B−RobotSeg, E=CAD amodal−RobotSeg를 별도 PNG로 저장했다. CAD는 amodal이고, RobotSeg도 GT가 아니다.

## 검수와 테스트

[Windows 6장 검수 ZIP](BB100_RobotSeg_6frame_review.zip)을 통째로 압축 해제하고 `index.html`을 열면 원본 전체 화면의 빨간 RobotSeg overlay와 확대된 CAD/SAM/A~E 비교를 볼 수 있다. 전체 화면은 예측이 관심 영역 바깥에 있는 실패를 확인하는 데 필요하다. 각 PNG는 후보이며 검수 완료나 GT가 아니다.

6장에 대해 출력 PNG 1280×720·단일 채널 0/255, `C=A∧¬RobotSeg`, `D=B∧¬RobotSeg`, 로그의 픽셀 수, A=C와 B=D 픽셀 일치, ZIP CRC 및 이미지 링크를 확인했다. Linux headless Firefox에서 6개 카드, 12개 이미지, 36개 mask 링크를 확인했다. Windows Chrome 실기기에서는 시험하지 않았다. Phase 12에 기록된 원본 307개 해시는 유지됐고, 사용자가 제공한 RobotSeg checkpoint 및 각 사용 RGB/CAD/SAM 파일도 추론 전후 해시가 같았다. 기존 Phase 16A 결과는 수정하지 않았다.
