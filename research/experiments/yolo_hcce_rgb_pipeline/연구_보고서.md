# YOLO11n + 공식 HCCEPose RGB-only 파이프라인 연구 보고서

2026-11-09. **학습된 YOLO가 GT ROI 없이 RGB에서 bbox를 검출하고 공식 EfficientNet-B4 HCCEPose와 PnP를 실행하는 파이프라인을 구축했다.** 실사 개발27 조건부 평가에서 검출 27/27, PnP 26/27, 명시적 대칭 ADD@0.1d 17/27이다. 개발27은 독립 테스트셋으로 검증되지 않았으며 GT 불확실성이 있어 실사용 정확도나 독립 일반화 성능으로 주장하지 않는다.

## 데이터와 누출 방지

- detector 학습·검증: `realistic_final100/train_pbr/000000`의 1280×720 PBR RGB, 같은 장면의 CAD pose, K, obj04 mesh를 이용했다. CAD는 공식 obj04와 같은 SHA-256이며 BOP 모델 mm 좌표계다. 학습은 기존 split의 장면 0,1,2,3,5,6,7,8에서 80장, 검증은 장면 4,9에서 20장이다. 두 split 사이 RGB SHA-256 일치는 0건이다. 합성 장면 및 배경의 통계적 상관은 남을 수 있다.
- PBR의 CAD amodal bbox는 모델 정점을 K와 pose로 투영해 만들었다. 100장 모두 양의 깊이·영상 내 경계·크기·회전 행렬 검사를 통과했고, 독립적으로 저장된 PBR amodal 렌더 mask bbox와의 최대 좌표 차이는 0.912 pixel이다. 이는 두 생성 경로의 정합 검사이며 실사 visible bbox 정확도는 아니다. 라벨과 감사 기록은 `dataset/`, `pbr_label_audit.csv`, 예시 overlay는 `overlays/pbr_labels/`에 있다.
- 실사 개발27은 detector 학습·검증에서 전부 제외했다. RAW→개발27 K,D 보정, 출력 K=원 K, crop/resize 없음. 개발27 원본과 PBR의 이미지 SHA-256 동일 항목은 없지만 해시는 촬영 세션 독립성을 보증하지 않는다. 기존 Oracle 21/27 기준선은 그대로 보존했다. 66,68,70,72,73의 pose 품질은 기존부터 불확실하다.
- BB100은 검출기 학습에서 제외했다. 기존 감사상 BB와 개발27 원본 exact SHA 일치는 0건, BB는 한 촬영 세션이며 36개 수치상 서로 다른 pose, 시간·pose 연결 그룹 36/64장이다. BB D 출처 및 pose 정확도가 독립 검증되지 않아 실사 자동 라벨의 품질 gate를 통과했다고 판단하지 않았다. 두 그룹 및 개발27 간 독립성도 미확인이다. BB 보정 이미지 생성 등 기존 결과는 수정하지 않았다. 자세한 시간·로봇 step은 `../official_rgb_pose_advanced_20261108/bb100_audit.csv`.
- CAD 투영 bbox는 gripper에 가려진 영역도 포함하는 **amodal bbox**다. 실사 마스크나 visible GT를 사용하거나 생성하지 않았다. 실사 개발27 CAD bbox는 평가 지표 계산에만 사용했다.

## 사전학습 YOLO 학습

Ultralytics 8.4.207 YOLO11n COCO pretrained, 단일 클래스, 이미지 640, batch 8, seed 42, patience 15, 최대 80 epoch, GPU 0, AMP다. 로그에는 pretrained layer 493/499 전이가 기록됐다. 80 epoch 학습 완료, 기록된 최대 학습 GPU 메모리는 약 1.49 GiB다. 합성 val20에서 best checkpoint의 P/R=0.998/1.000, mAP50=0.995, mAP50–95=0.990이지만 이는 적은 유사 합성 장면의 결과이며 실사 성능이 아니다. 학습 설정·곡선·체크포인트는 `train_config.yaml`과 `runs/yolo11n_pbr_attempt3/`에 있다. 공식 HCCEPose는 strict=True 로드한 채 가중치를 고정했다.

초기 학습 실행은 환경에 `pyparsing`이 없어 시작 전 실패했고, 두 번째는 첫 epoch 후 checkpoint 저장 시 `polars`가 없어 실패했다. 각 로그·실패 실행을 보존하고 새 실험 `.venv`에만 의존성을 설치해 세 번째에 성공했다. 원본 코드·기존 환경과 가중치를 학습 목적으로 바꾸지 않았다.

### Detector 상세

conf≥0.25, NMS IoU 0.45, 한 장에서 가장 높은 confidence의 bbox 하나를 선택했다. CAD amodal bbox를 기준으로 IoU≥0.5인 top-1 검출은 25/27이다. top-1 기준 precision 25/27=0.926, recall 25/27=0.926이다. 이는 모든 제안 박스를 고려한 표준 검출 AP나 사람이 만든 visible bbox 기준 지표가 아니다. GT pose가 의심되는 프레임에서는 bbox 정답 자체도 불확실하다.

## 추론 구성과 검증

`run_inference.py`는 RGB와 K를 입력받아 detector→최고 점수 bbox→기존 square padding/crop 1.5→공식 HCCE front/back decode→front PnP→R,t 및 CAD overlay를 수행한다. pose/ROI GT는 모델 입력에 넣지 않는다. 공식 네트워크의 원래 `inference_batch`와 분리된 decode의 mask, front/back XYZ 및 이미지 좌표가 픽셀 단위로 일치함을 실행 시 검사했다. `cli_smoke/`는 RAW 026에서 보정부터 pose 성공까지 실제 실행한 결과다. 별도 높은 threshold 검출 실패 검사 `cli_miss_test/`는 bbox와 R,t가 null이며 GT fallback이 없다. CLI 첫 호출에는 model warmup과 일치 검사가 포함되어 냉시작 지연이 크게 나온다.

완료 후 이전 실험이 기록한 원본·체크포인트 등 85개 입력 SHA-256을 모두 다시 계산해 일치했다. 이는 전 저장소 전수 불변성 검사는 아니다. 공식 가중치 SHA-256 `224c0869e20be8c9825b77925837e98f0e4c31ae1006361cddd1b46e0cb48ffc`, 새 YOLO best `949af2e2aa7532d5945bb197b05ef9bc1c943a8ff55b23732043fc88899320c8`, 다운로드 사전학습 `0ebbc80d4a7680d14987a577cd21342b65ecfd94632bd9a8da63ae6417644ee1`다. 상세 해시와 분할은 `dataset_manifest.json`, `split_manifest.json` 참조.

## 판단과 다음 단계

**기술적 파이프라인 GO, 실서비스·독립 일반화 평가 NO-GO.** 새 detector는 기존 smoke 대비 실사 개발27에서 검출이 향상됐지만 oracle ROI 대비 pose 성공이 4장 낮고, 작은 단일 세션 합성 데이터로 학습했으며 독립 실사 테스트가 없다. detector miss, bbox 저IoU, PnP 및 pose 실패는 CSV에 분리했다. 실사 점수에 맞춰 confidence나 ROI scale을 반복 튜닝하지 않았다.

다음은 독립 날짜·배경·로봇 주기 촬영과 K,D·pose 검증, 신뢰할 수 있는 실사 bbox 확보, 장면 그룹 단위 PBR/실사 혼합 detector 학습, 별도 검증군에서 bbox augmentation과 ROI scale 탐색이다. 가림·배경 혼동·calibration·대칭 또는 GT 오류는 대응하는 독립 근거를 얻은 뒤 분류한다. 카메라 입력·undistortion·overlay를 포함한 실제 스트림 속도, 장면 내 다중 객체와 false positive 평가도 필요하다. HCCEPose fine-tuning은 이번에 수행하지 않았다.
