# Phase 16A-2R — RobotSeg 그리퍼 분할 사전 조사

## 판정: BLOCKED — 실제 RobotSeg 추론 미실행

공식 RobotSeg 추론 코드는 `gripper` 범주를 지원한다. 그러나 **공식 체크포인트를 확보하거나 실제 텐서 구조를 확인하지 못했으므로, 이 서버와 BB 그리퍼에서의 실행·분할 성능은 미검증**이다. 10장 추론, 그리퍼 mask 및 RobotSeg 차집합 C/D/E는 생성하지 않았다. 모델의 이름이나 기존 SAM·flow 결과를 RobotSeg 출력으로 대체하지 않았다.

공식 OneDrive 체크포인트 링크는 서버에서 리다이렉트 후 HTTP 403을 반환했고, 익명 OneDrive 메타데이터 API는 HTTP 401을 반환했다. 따라서 `robotseg.pt`의 실제 크기와 SHA-256은 **알 수 없다**. Hugging Face의 공개 모델 검색에서도 `robotseg` 이름의 모델은 확인되지 않았다. 파일은 다운로드하지 않았다. GitHub API가 보고하는 저장소 크기 580,208KiB(약 567MiB)는 실제 clone 전송량이나 체크포인트 크기와 다르며, 사용자의 대용량 다운로드 제한에 따라 전체 clone도 실행하지 않았다. 코드 확인을 위해 공식 commit의 작은 텍스트 파일만 따로 저장했다.

## 공식 코드와 구조

- 공식 [RobotSeg 저장소와 README](https://github.com/showlab/RobotSeg), 조회 commit `dafb8c0d507276e2f96d2b07ac3661a7b3a41a5f`. 논문 [RobotSeg: A Model and Dataset for Segmenting Robots in Image and Video](https://openaccess.thecvf.com/content/CVPR2026/papers/Mei_RobotSeg_A_Model_and_Dataset_for_Segmenting_Robots_in_Image_CVPR_2026_paper.pdf)은 SAM 2 기반 모델에 structure-enhanced memory associator, robot prompt generator, label-efficient training을 제안한다. README의 41.3M 파라미터 및 성능은 저자 주장으로, 우리 환경의 측정값이 아니다.
- 저장소 코드는 Apache-2.0 라이선스다. 가중치와 학습 데이터에 적용되는 별도 조건, 의존 모델의 조건은 checkpoint를 실제로 확보한 뒤 확인해야 한다.
- `source_audit/test/demo.py`는 JPEG/PNG 이미지 디렉터리, `CATEGORY`의 `arm`/`gripper`/`robot`, `build_robotseg_video_predictor`를 사용한다. `add_new_robot(..., robot=CATEGORY)`는 프레임에 robot 범주를 전달하며 point/mask를 `None`으로 전달한다. 원본 해상도로 리사이즈한 logit을 반환하고 demo는 0 초과 threshold와 `guided_refine_mask` 후 overlay를 저장한다. 자동 프롬프트 기반 추론 코드가 공개됐다는 뜻이며, 단일 이미지 실행·우리 그리퍼에 대한 zero-shot 품질은 시험하지 않았다.
- `source_audit/test/inference_auto_semi_vrs.py`의 auto 분기 역시 `add_new_robot`를 사용한다. 그 평가 스크립트는 GT·메타데이터를 읽어 IoU 등을 계산하므로, 코드 전체를 BB에 그대로 실행하려면 입력 경로와 평가 구조를 적응해야 한다. GT 없이 추론 API를 호출한다는 것과 GT 기반 벤치마크 스크립트를 바로 실행할 수 있다는 것은 다르다.
- `robotseg/configs/robotseg-infer.yaml`은 Hiera 기반 image encoder와 memory attention, robot prompt generator, 내부 image_size 1024를 설정한다. `build_robotseg.py`는 checkpoint의 `model` state_dict를 읽으며 기본 strict 로드에서 누락·초과 키를 허용하지 않는다. 다만 checkpoint를 받지 못해 실제 키, 텐서 shape, 출처와 hash는 미확인이다.
- README에 제시된 VRS의 10개 로봇은 Franka, Fanuc Mate, UR5, Kuka iiwa, Google Everyday Robot, MobileALOHA, xArm, WidowX, Sawyer, Hello Stretch다. 우리 SMT 장비의 구체적 그리퍼가 학습에 포함됐는지는 확인되지 않았다. 로봇 이름 목록만으로 포함 또는 제외를 단정하지 않는다.

## 의존성·서버 호환성

공식 README 예시는 Python 3.11, PyTorch 2.5.1, torchvision 0.20.1 및 cu121 환경이다. `setup.py`의 요구사항은 torch≥2.5.1, torchvision≥0.20.1, numpy, hydra-core, iopath, pillow, kornia 등이다. 연결 성분 후처리 CUDA 확장을 기본 빌드하지만 `ROBOTSEG_BUILD_CUDA=0`로 끌 수 있고, 코드에는 빌드 실패 시 일부 후처리가 제한될 수 있다는 안내가 있다.

현재 실험 서버는 RTX 5090, NVIDIA driver 595.99.02이며 기존 연구 환경은 Python 3.10.16, PyTorch 2.8.0+cu128이다. `nvcc`와 `/usr/local/cuda*`는 조사 경로에서 확인되지 않았다. 공식 예제의 cu121 조합과 RTX 5090의 실제 조합, CUDA 확장 및 기존 torch 2.8.0 조합은 **시험하지 않았다**. 코드 조건의 버전 범위가 맞는 것과 GPU kernel·checkpoint 실행 성공은 다르다. 제공된 `_C.so`도 ABI/아키텍처 호환성은 미검증이다.

기존 환경을 변경하지 않았고 대용량 의존성 설치나 별도 가상환경 생성도 수행하지 않았다. 체크포인트와 다운로드 범위가 확인되면 독립 가상환경에 최소 의존성을 설치하고, 원본 환경을 수정하지 않는 방식으로 strict 로드 및 GPU 유휴 상태 확인 후 소규모 smoke test를 수행할 수 있다. CUDA 확장 없이 작동하는 경로와 후처리 차이는 별도로 검증해야 한다.

## 10장 산출물과 기존 방법

부분 가림 075, 235, 099, 221, 340, 359 및 가림 없음 043, 247, 383, 420을 준비했다. [representative_status.csv](representative_status.csv)에서 10장 모두 RobotSeg 마스크가 `NOT_RUN`, C/D/E가 `NOT_CREATED`다. 기존 A=SAM, B=CAD∩SAM은 Phase 16A-1 후보를 읽어 복사했으며 자동 GT가 아니다. CAD는 amodal이다.

[Windows 대체 검수 ZIP](BB100_robotseg_blocked_review_windows.zip)은 기존 10장의 RGB·CAD·SAM·교집합과 가능한 6개의 기존 LiteFlowNet 비교를 오프라인으로 제공한다. 각 페이지에 **RobotSeg 미실행**을 명시한다. 이것은 요청된 RobotSeg 결과 이미지의 대체 검토 자료이지 RobotSeg 성능 비교가 아니다.

페이지는 외부 라벨링 도구에서 이미 보정한 PNG를 받아 1280×720, 8비트 단일 채널, 불투명 0/255 형식을 확인한 뒤 사용자가 별도 `manual_reference_UNVERIFIED.png`로 다운로드하도록 지원한다. 이 UI는 픽셀 편집을 하지 않으며 파일 형식만 검증하고 참조 GT의 내용·독립성을 인증하지 않는다. 수동 보정된 참조는 제공받지 못해 IoU/Dice는 계산하지 않았다. 기존 원본 파일에는 쓰지 않는다.

## LiteFlowNet 비교 및 질문별 답변

이전 Phase 16A-2F에서는 여섯 쌍의 실제 dense flow를 계산했으나, 221→222의 움직임 차감이 SAM 후보 17,075픽셀 중 16,861픽셀을 제거하는 실패 위험이 있었다. 움직임은 그리퍼 정체성을 보장하지 않는다. RobotSeg는 이번에 실행하지 못했으므로 **RobotSeg 대 LiteFlowNet, SAM+RobotSeg 대 SAM+LiteFlowNet의 성능 비교는 보류**한다.

1. **우리 그리퍼 분할:** 미검증. checkpoint 없이 추론하지 않았다.
2. **기존 SAM 대비 그리퍼 제거:** 미검증. 독립 참조도 없다.
3. **CAD 결합 개선:** 미검증. RobotSeg 기반 교집합·차집합을 만들지 않았다.
4. **실패 프레임:** RobotSeg 자체에 대해서는 시험하지 않아 알 수 없다. 기존 SAM은 043 등에서 구멍을 메웠고 기존 LiteFlowNet은 221→222에서 객체 후보 과삭제 위험을 보였다. 서로 다른 모델의 결과를 혼동하지 않는다.
5. **100장 도입 가치:** 가설 검증을 위한 소규모 시험 가치는 있으나 현재는 근거 부족으로 **확대 NO-GO**다.

## 검증·다음 단계

ZIP 링크와 CRC를 검사했고 Linux headless Firefox에서 10장 카드, 미실행 경고, 단일 채널 참조 PNG 형식 검사 및 CSV 내보내기를 시험했다. 실제 Windows Chrome은 시험하지 않았다. Phase 12의 소스 해시 307개와 공식 HCCEPose checkpoint 해시는 기존 기록과 같다. GPU 학습과 RobotSeg 추론은 실행하지 않았다.

공식 링크 접근이 가능한 환경에서 `robotseg.pt`의 크기·출처·이용 조건을 확인하고 서버의 별도 경로에 제공하면 파일 hash 및 state_dict를 검사할 수 있다. 대용량 코드/가중치/의존성이 필요한 경우에는 사용자 지시대로 다운로드 범위와 용량을 먼저 확인한다. 이후 별도 환경과 GPU 점유 확인, 부분 가림 6장 우선 추론, 나머지 4장, 수동 참조 마스크와의 독립 비교 순으로 진행한다. 후보 C/D/E는 실제 RobotSeg mask가 생성되고 형식·좌표가 검증된 뒤에만 만든다.
