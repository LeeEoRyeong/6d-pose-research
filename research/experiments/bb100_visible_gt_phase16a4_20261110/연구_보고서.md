# Phase 16A-4 — BB100 전체 Visible Mask 후보와 검수 확장

## 현재 상태

100장 각각에 CAD amodal A, SAM2 B, CAD∩SAM2 C, SAM2−RobotSeg D, CAD∩SAM2−RobotSeg E 후보를 실제 생성·검증했다. 이들은 모두 자동 후보이며 GT가 아니다. Phase 16A-3에서 사용자가 승인한 **10장과 해당 37개 저장 버전(파일 185개)의 이력**을 별도 작업 디렉터리에 보존했고, 나머지 **90장은 미저장 DRAFT**다. 전체 100장 Visible Mask GT 구축은 사람의 90장 검수가 필요해 아직 완료되지 않았다. 추가 자동 승인은 없었다.

100장 편집기는 실행 중이며 미작업 프레임에서 D가 기본 선택된다. 다만 D는 단순히 편집 시작점이며 더 정확하다는 보장은 없다. 특히 093/095는 RobotSeg가 B 후보의 절반 이상을 제거해 B/C와 비교 검수가 시급하다. 원본 데이터·Pose·이전 실험과 승인본을 변경하지 않았고 HCCEPose 학습을 실행하지 않았다.

## 후보 생성과 출처

- A: Phase 15의 CAD 렌더를 각 프레임에 연결. 36개 고유 Pose의 amodal mask를 재사용했다.
- B: 기존 Phase 16A-1 SAM2 후보 10장 재사용, 나머지 90장은 로컬 SAM 2.1 Hiera Tiny로 실제 추론했다. CAD bbox와 CAD 내부의 어두운 점을 사용한 자동 프롬프트는 실제 객체 foreground라는 보장이 없다. SAM 최고 내부 점수도 GT 정확도가 아니다.
- C: `B ∩ A`. CAD가 빗나가거나 보이는 외곽이 벗어나면 정상 객체 픽셀도 빠질 수 있다.
- RobotSeg: 기존 Phase 16A-2R 원본 자동 gripper mask 6장 재사용, 나머지 94장은 실제 단일 이미지 자동 gripper 추론을 실행했다. D=`B − RobotSeg`, E=`C − RobotSeg`. ROI guided 실험의 수동 점은 전체 자동 결과에 사용하지 않았다.
- 각 단계 직전 GPU compute 점유를 확인했다. SAM PyTorch peak allocated/reserved 583,890,944/679,477,248 bytes, RobotSeg 612,336,128/710,934,528 bytes. 각각 드라이버 전체 GPU 사용량은 아니다. SAM checkpoint SHA-256 `7402e0d864fa82708a20fbd15bc84245c2f26dff0eb43a4b5b93452deb34be69`; RobotSeg 사용자 제공 checkpoint SHA-256 `1384c38c4f313487a32503025d4566ac1d815f6be983199362fc4af19aaa06a2`. RobotSeg는 이전 strict 로드 검증을 재사용했다.

A–E 각 100개, 총 500개 1280×720 단일 채널 0/255 PNG의 형식과 연산을 확인했다. RobotSeg 출력도 별도 R 100개로 보존한다. 출력 경로는 `candidates/A/`–`E/`, `candidates/R/`이며 RGB·기존 마스크는 변경하지 않았다.

## B/C/D 차이: 정답 점수가 아님

[100장 후보 차이와 구조 진단](candidate_analysis_with_accepted.csv):

- **D=B는 95/100장**, 차이가 있는 경우는 5장이다. 기존 SAM에서 RobotSeg가 제거한 픽셀 수는 중앙값 0, 최대 12,315다. 승인된 대표 10장에서는 D와 B가 모두 같다. 따라서 그 10장에서 사용자가 관찰한 D와 C의 차이를 RobotSeg 제거 효과로 해석할 근거는 없으며, B와 C의 **CAD 교집합 적용 여부**가 계산상 차이다. 이것은 사용자의 시각적 관찰을 부정하는 것이 아니라 원인을 구분한 것이다.
- B와 C는 100/100장 다르며 픽셀 차이 중앙값 1,577.5다. CAD 교집합은 CAD 바깥 후보를 제거하고 CAD 투영 구멍을 복구하지만, 실제 보이는 BB가 CAD 투영 밖에 있거나 Pose가 맞지 않으면 정상 표면도 제거할 수 있다. 반대로 B는 실제 구멍을 채울 수 있다.
- D가 B를 바꾼 프레임: 077은 15px(0.1%), 090은 1,510px(11.2%), 093은 6,736px(50.1%), 095는 12,315px(92.2%), 358은 31px(0.2%). 특히 **093과 095의 D는 과삭제 가능성을 우선 확인**한다. 제거량은 그리퍼 정답량이나 오삭제율이 아니다.
- CSV는 CAD 투영의 닫힌 구멍과 B/D에서 채워진 비율을 구조적 참고로 기록한다. CAD pose 오차, 가림 및 미투명 내부가 있으므로 그 수는 실제 구멍 정답 점수가 아니다. 실제 보이는 표면 누락과 hole 정합은 ACCEPTED 참조가 있는 10장에 한해 별도 FP/FN으로 기록하고 나머지 90장은 UNKNOWN으로 남겼다.

기존 10장 ACCEPTED 참조와 128 제외 valid 영역으로 사후 산출한 참고 매크로 IoU는 B=D 약 0.8988, C=E 약 0.9976이다. **이 수치는 독립 모델 성능 비교가 아니다.** 승인된 10장 모두 C 초기 후보로 시작했고 그중 5장은 초기 C와 수정 픽셀이 0이다. 참조가 비교 대상 C로 초기화돼 C에 유리한 강한 순환·초기화 편향이 있다. 사용자 육안 판단과 이 수치의 불일치를 우열의 증거로 단정하지 말고 원본 RGB, 구멍과 실제 표면을 별도 검수해야 한다. 결과: [10장 평가 CSV](evaluations/20261110T135546Z_253ab51a/summary.csv). 그리퍼 전용 정답이 없으므로 gripper 전용 precision/recall은 없다.

## 편집기와 보존

서버의 `127.0.0.1:7870`에서 새 100장 편집기가 실행 중이다. Windows에서 다음 SSH 포워딩을 연 뒤 Chrome에서 `http://127.0.0.1:7870`으로 접속한다.

```bash
ssh -L 7870:127.0.0.1:7870 oylee@<연구서버주소>
```

서버 재시작:

```bash
cd /home/oylee/projects/HCCEPose_experiments/bb100_visible_gt_phase16a4_20261110
/home/oylee/projects/HCCEPose_experiments/yolo_hcce_rgb_pipeline/.venv/bin/python -B app.py --port 7870
```

각 프레임에서 D를 확인하고 B/C 미리보기 버튼으로 비교한다. 0=배경·그리퍼·실제 구멍, 128=불확실, 255=실제 보이는 BB다. 물체 누락을 채우고 그리퍼, 구멍, 외곽·그림자를 검수해 DRAFT 저장→재로드 확인→사용자 확인 후 ACCEPTED 저장 순서로 진행한다. 브러시, 지우개, ignore, 확대, Undo/Redo를 제공한다. D가 B를 변경한 5장은 목록에 차감량 경고가 표시된다. `annotations/frame_status.csv`에는 상태, 초기 후보, 원본 후보 대비 수정 픽셀, Ignore, 전경 면적, 승인 시각, 저장 경로가 기록된다. 기존 승인 10장의 초기 후보는 C로 그대로 유지하며 D로 강제 초기화하지 않는다.

기존 Phase 16A-3 승인본은 전체 버전별 파일을 해시 확인하여 **새 디렉터리로 복사한 스냅샷**이다. 이전 편집기 7867과 새 편집기 7870의 후속 저장은 자동 동기화되지 않는다. 이후에는 **새 7870 편집기만 사용**하고, 양쪽에서 동시에 편집하지 않는다. 이전 원본 10장과 37개 저장 버전의 파일 185개는 덮어쓰지 않았다. 기존에 128이 있던 마스크의 ignore도 그대로 보존한다.

## 학습·BOP 준비 상태

[bop_preparation_manifest.csv](bop_preparation_manifest.csv)는 100장 RGB·Pose·K·CAD와 승인된 10장의 mask/valid 경로를 연결한 현재 시점 스냅샷이다. 90장의 GT 경로는 비어 있고 split은 전부 UNASSIGNED다. 검수 진행 후 `create_manifest.py`를 실행하면 새 이름의 스냅샷이 생성된다.

작업 마스크는 원본 크기 uint8의 0/128/255다. 이진 전경 PNG와 valid PNG는 쌍으로 저장되며 128을 배경으로 확정하지 않는다. Ignore가 남으면 이진 mask 단독을 완전한 BOP GT로 사용하지 않는다. 물리적 배치 분리, 공식 대칭 HCCE 좌표 정합, 실제 학습 로더 및 90장 승인 모두 미완료이므로 **HCCEPose 실사 파인튜닝은 BLOCKED**다. 100장 승인 이후에도 이 조건을 별도로 검증해야 한다.

## 검증

100장·후보 500개를 로드하고 마스크 형식과 C/D/E의 집합 관계를 검사했다. 복사된 기존 10장과 버전 이력은 원본과 해시 일치했으며, 승인 마스크의 Ignore와 valid/foreground 저장본 관계도 통과했다. 임시 저장소에서 Linux headless Firefox로 100장 선택, D 기본값, B/C 미리보기, 200% 확대 좌표, 포인터, Undo/Redo, 저장·수정 픽셀과 Ignore를 시험했다. Windows Chrome 실기기는 미시험이다. 실서버의 상태는 승인 10, 미저장 DRAFT 90이다.
