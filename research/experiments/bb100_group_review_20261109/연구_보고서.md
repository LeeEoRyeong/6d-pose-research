# BB100 Pose 그룹별 시각 검수 준비

2026-11-09. BB100의 기존 동일 pose 그룹 **36개, 100장**을 그대로 유지해 그룹 비교 자료와 Windows Chrome 오프라인 검수 패키지를 만들었다. 반복 그룹은 11개·75장, 단일 프레임 그룹은 25개다. 모든 그룹·프레임은 UNREVIEWED, 학습 상태 HOLD로 시작한다. 사람이 아직 검수하지 않았으며 실제 객체의 정지·이동과 GT 정확도는 UNKNOWN이다.

사용자는 객체가 움직일 때 Vision6D에서 pose를 다시 맞추고 정지한 프레임에는 기존 pose를 유지했다고 설명했다. **반복 pose는 의도된 정상 라벨링 방식이며 그 자체로 오류가 아니다.** 다만 같은 R,t가 기록된 모든 영상에서 물체가 실제로 같은 위치였는지는 각 영상의 육안 검수가 필요하다. 그룹 ACCEPT는 모든 프레임의 ACCEPT를 의미하지 않는다.

## 자료와 그룹 구성

Phase 10의 pose 그룹·100장 원본 라벨 JPEG·amodal 투영, Phase 12의 100장 확대/축 비교 이미지를 재사용했다. 기존 그룹 ID, frame ID, 촬영 시각 순서 및 36개 그룹 R,t를 보존하고 `group_metadata.csv`에 기록했다. 043→060의 복사 이력은 오류로 판정하지 않고 먼저 볼 그룹으로 표시했다. Phase 12 디렉터리에서 사용자가 내보낸 검수 CSV는 발견되지 않았다. 브라우저 localStorage는 서버 파일 검색으로 확인할 수 없으므로, 기존 Phase 12 CSV가 있다면 새 페이지에서 **사용자가 명시적으로 선택해 가져올 수 있다**. 가져오기는 이미 편집한 프레임을 건너뛰며 그룹 상태를 바꾸지 않는다.

각 반복 그룹의 비교 이미지는 촬영 순서의 첫 프레임(대표), 중간 프레임, 마지막 프레임, 첫 프레임 대비 객체 투영 ROI의 픽셀 차이가 가장 큰 프레임을 모은다(중복 선택은 한 번만 표시). 단일 그룹은 대표 한 장만 보여준다. 각 열의 위쪽은 라벨 JPEG 확대, 아래쪽은 동일 픽셀 crop의 CAD amodal 투영이다. GT pose가 수치상 같다는 사실과 실제 물체가 정지했다는 판정은 구분한다.

## 그룹별 이동 의심 지표 — 자동 판정 아님

기준 영상은 그룹의 첫 프레임이다. 기존 pose와 CAD로 정의한 고정 화면 ROI에서 amodal 지지영역을 5×5 kernel로 한 번 침식하고 다음을 계산했다. amodal 영역에는 그리퍼 등 가림 물체가 포함될 수 있어 실제 물체 전용 mask가 아니다.

- 회색 영상 ROI 평균 절대 차이와 두 영상의 중앙 밝기 차이를 뺀 보조 지표.
- Canny edge의 양방향 최근접 거리 중앙값 평균. 이 edge는 물체 외곽이나 구멍이라고 자동 식별하지 않는다.
- ROI의 고대비 특징점에 대한 전·역방향 일관성 1px 미만 KLT 추적 수와 중앙 이동량. 그리퍼·반사·텍스처가 함께 추적될 수 있고, 구멍이나 CAD 특징점의 신뢰할 만한 대응을 독립 검증한 것은 아니다.
- 촬영 순서와 첫 프레임으로부터의 시간. 단일 프레임에는 이동 추정이 없다.

모든 수치는 `motion_diagnostics.csv`, 그룹별 최대 수치와 선택된 프레임은 `group_metadata.csv`에 기록된다. 자동 수치는 검수 우선순위의 단서일 뿐 객체 이동, 가림, 반사, 경계 오류 또는 GT 정합 여부를 확정하지 않는다. 후자의 실제 상태는 모두 UNKNOWN이다.

P1은 Phase 10의 사람 검수 우선순위이며 GT 오류가 아니다. 043→060 이력 그룹을 맨 앞에 두고, 이전에 그리퍼와 투영 영역의 중첩을 관찰한 235 그룹을 그다음 표시한다(가림 정도는 미검증). 이후 P1 포함 그룹과 ROI 차이 순으로 정렬한다. 기존 관찰에서 235는 그리퍼가 CAD 투영 영역과 겹쳤지만 가림의 정도나 다른 그룹의 반사·경계 오류는 자동으로 확정하지 않았다. 검수자가 경계 UNCLEAR를 기록한 그룹은 페이지에서 별도 필터링할 수 있다.

## 검수 및 학습 후보 절차

1. ZIP 전체를 Windows에 복사해 압축을 풀고 `index.html`을 Chrome으로 연다. HTML 하나만 복사하면 이미지가 표시되지 않는다. 네트워크 의존성은 없다.
2. 043/060을 먼저 검수하고, 같은 화면 ROI에서 물체 외곽·구멍·평면 경계와 CAD 윤곽, 그리퍼 가림과 반사로 인한 차이를 분리해 확인한다. 실제로 움직임을 판단할 수 없다면 UNKNOWN/UNCERTAIN으로 남긴다.
3. 그룹 ACCEPT/CORRECT/UNCERTAIN은 그룹 검수 기록이다. 각 프레임의 상태와 이동 의심 여부는 별도로 지정한다. 그룹 ACCEPT만으로 프레임 상태가 바뀌지 않는다.
4. 필요한 경우 프레임에 **명시적 후보 표시**를 한다. 후보 CSV에는 그룹 ACCEPT, 프레임 ACCEPT, 후보 체크가 모두 있고 그 프레임이 MOVEMENT_SUSPECTED가 아닌 행만 표시한다. 이는 추가 검토를 위한 후보 목록이며 모든 행의 training_status는 HOLD다. 정밀 GT 인증·실제 학습 승인이 아니다.
5. localStorage는 브라우저별·오리진별로 소실될 수 있으므로 그룹 CSV·프레임 CSV를 자주 내보낸다. Phase 12의 CSV와 이 페이지에서 내보낸 그룹·프레임 CSV는 파일 선택으로 명시적으로 가져오되 기존 편집은 보존된다. 원본 Phase 12 자료는 수정되지 않는다.

각 100장 프레임의 더 큰 Phase 12 비교 이미지는 `frames/`에서 열 수 있다. `group_metadata.csv`에는 보수적 연결 그룹 ID도 포함해 향후 그룹 단위 split을 준비할 수 있다. 두 연결 그룹도 같은 촬영 세션이므로 독립 테스트셋으로 취급할 수 없다.

## 검증과 한계

기존 pose 그룹 36개·프레임 100개를 대조했고 동일 그룹의 R,t 정확 일치와 모든 ID 대응을 확인했다. `305`개 참조 파일은 생성 전후 해시가 일치했다. 자동 지표에는 검증된 visible mask·독립 객체 추적 GT가 없으며, 후보 GT로 정의한 ROI에 물체가 맞는지도 미검증이다. 카메라는 동일 Tapo라는 사용자 진술과 제공된 전처리 기록에 근거하고 GT 정확도를 별도로 인증하지 않는다. 모델 학습과 GPU 추론은 실행하지 않았다.

HTML은 모든 데이터가 내장되고 이미지와 CSV는 상대경로다. ZIP에는 36개 그룹 이미지, 100개 프레임 이미지와 검수 CSV/문서가 함께 포함된다. 자동 링크·ZIP 경로 및 각 이미지 존재 검사는 별도 검증 결과를 참고한다. 실제 Windows Chrome 렌더링은 이 서버에서 실행 가능한 브라우저가 없을 경우 미검증으로 남기며, JavaScript 기능은 모의 DOM에서 smoke test한다. ZIP은 실사 이미지와 GT pose 수치를 포함하므로 적절히 보관한다.
