# Phase 16A-2F — LiteFlowNet 기반 객체·그리퍼 움직임 분리 가능성

## 결론

LiteFlowNet의 공식 재구현과 사전학습 default 가중치는 이 서버의 RTX 5090에서 **실제 실행됐다**. 여섯 쌍의 dense forward/backward flow는 객체와 그리퍼 주변 움직임을 시각적으로 살피는 데 추가 정보를 제공한다. 다만 flow는 이동하는 대상의 종류를 구별하지 못하고 그리퍼가 정지하거나 객체와 함께 움직이면 분리가 불가능할 수 있다. 여섯 쌍의 탐색 결과는 SAM 기반 visible mask가 좋아졌다는 증거를 제공하지 않았다.

특히 221→222에서는 움직임 후보를 SAM에서 일괄 차감하면 SAM 후보 **17,075px 중 16,861px(약 98.7%)**이 사라진다. CAD∩SAM도 16,116px 중 15,962px이 제거된다. 움직이는 물체를 그리퍼로 오인해 제거하는 명백한 위험 사례다. **100장 Visible Mask GT 자동 구축에 도입: NO-GO.** 사람 검수 보조 또는 독립적으로 검증된 가림 영역 추정의 연구 대상으로만 추가 검토할 수 있다. GPU 본 학습은 하지 않았다.

## 구현·환경 및 라이선스

- [sniklaus/pytorch-liteflownet](https://github.com/sniklaus/pytorch-liteflownet)는 논문 원저자의 공식 Caffe 구현을 PyTorch로 재구현한 별도 프로젝트다. 코드 라이선스는 GPL-3.0이고, README는 원저자 자료의 연구 목적 사용 조건도 확인하도록 요구한다. 배포나 상업적 활용 전 [원저자 조건](https://github.com/twhui/LiteFlowNet#license-and-citation)과 가중치 이용 조건을 별도 검토해야 한다. 재구현 저자 역시 수치적 차이와 구현 정확성의 한계를 명시한다.
- checkout commit `a81ea7b0d23306412b2b96a55ff28dcc1ae076d8`. [원본 run.py](https://github.com/sniklaus/pytorch-liteflownet/blob/master/run.py)에서 지정한 `network-default.pytorch`를 HTTPS로 내려받았다. SHA-256 `801de3f3f7df8dc0c5935e91f84852ebd3481ab60d89f175027a5321eebd95dc`. 원본 구현의 `load_state_dict`는 strict 기본값으로 성공했다. 원본 저장소와 HCCEPose 코드는 수정하지 않았다.
- 새 `.venv`에 CuPy 13.6.0과 NumPy 1.26.4를 설치하고 기존 환경의 PyTorch 2.8.0+cu128/OpenCV를 `.pth`로 읽기 전용 참조했다. 완전 독립 복제는 아니며 기존 Python 패키지 경로에 의존한다. CuPy CUDA raw kernel과 모델 correlation 호출이 성공했다. PyTorch/CUDA 12.8 및 RTX 5090에서 확인했다.
- 원본 `estimate()`는 사용자가 예시 크기 외 입력을 사용할 때 주의를 환기하도록 1024×436 assertion을 둔다. 1280×720 BB에 적용하기 위해 **새 래퍼에서만** 이 예제 크기 제한을 건너뛰고 BGR 입력, 32 배수 bilinear 보간, 출력 보간 및 x/y 벡터 축척 보정을 원본대로 구현했다. 이는 원본 작성자의 경고를 없애거나 임의 크기에서 정확성을 보증한다는 뜻이 아니다. CUDA stream은 CuPy ExternalStream으로 PyTorch 현재 stream에 맞췄다.
- 동일 이미지를 양쪽에 넣은 sanity에서 flow 크기 중앙값 0.109px, p95 0.279px이었다. 0이 아닌 추정 잡음이 존재한다. 실사 정답 flow가 없으므로 이 값은 실제 flow 정확도 검증이 아니다.

## Forward/backward와 결합 규약

각 쌍에서 1280×720 dense forward와 backward flow를 실행했다. forward 좌표로 backward를 bilinear 표본화하고 `|F(x)+B(x+F(x))| ≤ 1px + 0.05(|F|+|B|)`를 일치 휴리스틱으로 사용했다. 시야 밖이나 불일치 픽셀을 별도 PNG로 보존했다. 이는 가림 또는 잘못된 flow 가능성을 보여주는 진단이고 독립된 가림 GT나 보정된 신뢰도가 아니다. 동일하게 잘못된 순·역 추정도 일치할 수 있다.

배경 후보는 양쪽 CAD 투영을 확대한 바깥 영역이며, 기계가 포함될 수 있다. 일치한 배경의 중간 flow 벡터를 뺀 잔차 크기가 해당 배경 잔차의 p99보다 큰 픽셀을 **움직임 후보**로 표시했다. 이 임계값은 각 영상의 탐색적 상대 기준이며 실제 그리퍼 확률이나 보증된 신뢰도가 아니다. Phase 15B 배경 품질이 불통과이거나 유효 배경이 부족하면 차감을 사용하지 않는다.

- A: 원래 SAM.
- B: 원래 CAD∩SAM.
- C: SAM에서 움직임 후보를 제거한 탐색 후보.
- D: CAD∩SAM에서 움직임 후보를 제거한 탐색 후보.

C/D는 **방법의 실패 가능성을 관찰하기 위한 실험용 차집합**이며 그리퍼로 확정된 픽셀을 뺀 결과가 아니다. 모든 원본 후보와 차감 전후 mask, 움직임 후보 및 FB 불일치를 별도 보존했다. 변경량은 `pairs.csv`에 있으며 마스크 분할 정확도나 IoU 점수가 아니다.

## Phase 15B 및 SAM과의 비교

- **추가 정보:** SIFT/ORB는 희소 대응점과 강체 근사이고 LiteFlowNet은 픽셀마다 흐름을 제공한다. 235→237의 색상 및 FB 불일치 그림은 그리퍼 주변 변화를 검토하는 데 도움이 될 수 있다. 단, 이 경계는 기존 배경 gate가 실패했고, 그리퍼 픽셀 위치나 물체 상태의 독립 정답을 제공하지 않는다.
- **배경 대비 움직임:** 099→101의 CAD 영역 flow 크기 중앙 16.19px, 배경 영역 0.26px은 Phase 15B SIFT/ORB의 상대 변위 약 16.48/17.39px과 유사한 규모다. 서로 다른 추정기라도 같은 영상과 구조를 사용하므로 서로 독립인 실제 정답은 아니다. 이 쌍은 배경 잔차 p99가 약 17.24px로 높아 차감된 SAM 픽셀은 111개뿐이다. p99는 배경 후보에 포함된 기계 움직임의 영향을 받을 수 있다.
- **결합 실패:** 221→222에서는 FB 일치 비율이 CAD 내 96.6%여도 움직이는 SAM 영역을 거의 전부 지웠다. 순·역 일치가 객체 정체성이나 올바른 분할을 보장하지 않음을 보여준다. 235/340은 배경 불안정으로 차감을 중지했다.
- **SAM 단독 대비:** Phase 16A-1에서 SAM이 물체 구멍을 메우는 사례가 이미 관찰됐다. LiteFlowNet은 정적 구멍을 별도로 복원하지 못하고, 움직이는 물체의 픽셀을 지울 수 있다. 독립적인 visible pixel GT가 없어 정확도 개선/악화를 정량적으로 단정할 수 없으나, 221의 큰 삭제는 자동 차감의 구체적 실패 위험이다.

## 실행·재현 및 산출물

- [실험 쌍 CSV](pairs.csv), [환경 및 측정 JSON](summary.json), [검증 결과](validation.json).
- `flow/`에 쌍별 forward/backward float32 flow, FB 오차와 일치 mask를 압축 저장했다. `masks/`에는 SAM/CAD∩SAM의 전후와 움직임/불일치 후보를 보존했다.
- [Windows 오프라인 ZIP](BB100_liteflownet_review_windows.zip)을 전체 압축 해제하고 `index.html`을 열면 전후 RGB, flow 방향/크기, overlay, SAM·결합 후보와 차이, 불일치를 볼 수 있다. 이미지별 flow 컬러 밝기는 해당 쌍의 p95 크기로 정규화돼 다른 쌍 간 색상 밝기를 절대 속도로 비교할 수 없다. CSV 내보내기는 사람의 참고 기록일 뿐 GT 승인이 아니다.
- 모델과 상관 CUDA smoke 성공 후 6쌍 순·역 12회 및 동일 이미지 sanity 1회를 실행했다. PyTorch peak allocated 1,014,971,904 bytes, reserved 1,296,039,936 bytes이며 CuPy 또는 드라이버 총량과 동일하지 않다. GPU compute 작업이 없는지 직전 확인했다.
- 전체 flow는 유한값과 원본 해상도를 통과했고, 차집합과 배경 실패 시 미적용, ZIP 이미지·마스크 및 CRC를 검사했다. Linux headless Firefox에서 6개 페이지 카드와 이미지, 검수 CSV 내보내기 및 새로고침 복원 PASS. Windows Chrome은 실제 시험하지 않았다. 기존 Phase 12 입력 307개 해시 및 HCCEPose 공식 체크포인트 SHA-256이 보존됐다.

## 연구 판단

1. **실행:** 현재 하드웨어·별도 환경에서 정상 실행. 임의 크기 래퍼와 CuPy CUDA 의존성은 유지보수 비용이다.
2. **움직임 분리:** 일부 쌍에서 주변 변화의 시각화에 도움. 픽셀의 객체/그리퍼 정체성은 자동 확정 불가.
3. **SAM 대비 개선:** 입증되지 않았다. 221→222에서는 단순 차감의 큰 실패가 확인된다.
4. **구현 복잡도:** CuPy·CUDA 커널, stream, 가중치, 순·역 추론과 품질 정책이 추가된다. 현재 측정된 실익은 검수 보조에 한정되므로 자동 파이프라인 채택을 정당화하기 어렵다.
5. **최종 100장 GT:** 무검수 도입은 NO-GO. 향후 가림 없는 객체/그리퍼 분할 및 이동 정답이 있는 소수 참조 쌍에서, 작업 시간 절감과 오검출·누락을 평가한 뒤에만 재검토한다. Phase 15 split 및 HCCE 타깃 BLOCKED 판정은 그대로다.
