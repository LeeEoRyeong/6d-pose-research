# 공식 ITODD obj04 기반 RGB-only Pose 실험 보고서

작성일: 2026-11-08. 대상: ITODD obj04, 실험은 추론·진단만 수행. 원본 코드 및 체크포인트, 기존 결과를 수정하지 않았다. **현 단계에서는 공식 모델 A와 oracle ROI를 연구 기준으로 유지한다. 실제 검출 기반 시스템과 추가 학습의 Go 조건은 미충족이다.**

## 측정 결과와 재현

기존 평가기 `itodd_symmetry_eval_20261108/evaluate.py`의 입력·crop·HCCE decode·front PnP·대칭 오차를 두 모델에 공통으로 재사용했다. EfficientNet-B4 공식 및 ResNet34 baseline을 strict=True로 로드하고 실사 개발 27장 전체를 새로 평가했다. 공식 명시적 대칭 ADD@0.1d **21/27**, baseline **0/27**; PnP는 각각 27/27이다. 일반 ADD는 0/27, ADD-S는 공식 26/27, baseline 0/27이다. 두 모델의 프레임별 3개 오차와 PnP는 이전 결과에 대해 최대 차이 0으로 재현됐다. 공식 명시적 대칭 ADD 기준 실패 프레임: [78, 32, 72, 73, 83, 92]. 프레임별 결과는 `per_frame.csv`다. 개발27은 독립 최종 테스트가 아니며 프레임 66, 68, 70, 72, 73의 기존 GT 불확실성도 남아 있다.

공식 이산 대칭 S는 `T_m2c @ S`이며 `R'=R Rs, t'=R ts+t`. 공식 PLY 단위 mm, 임계값 13.9379 mm다. 기존 검증에서 동일 pose 세 오차 0, 대칭 적용 pose 명시적 대칭 ADD 0, ADD-S 0.7041 mm, 일반 ADD 74.2144 mm다. 대칭 이동 누락시 0.144095 mm 오차가 발생한다. 명시적 대칭은 모델 정의를 동치로 취급하므로 메시의 근사 대칭을 자동으로 완전하다고 증명하지 않는다. 실사 pose의 물리 단위·정확도는 별도 확인이 필요하다. 이 수치를 BOP AR과 비교하지 않는다.

기존 PBR Val20 결과는 재실행하지 않고 이전 공통 평가 결과를 참조한다: 공식 명시적 대칭 9/20, ADD-S 10/20, baseline 각각 1/20, 3/20. 공식 학습 PBR과의 정확한 파일 단위 중복은 미확인, 독립 검증으로 주장하지 않는다. 기존 baseline split과 checkpoint 선택을 변경하지 않았다.

## RGB detector 연결

기존 obj04 YOLO 가중치 `realistic_final100/yolo11/train_obj_s/smoke_train/weights/best.pt`는 별도 환경에서 로드했다. 1 epoch, 데이터 10%, pretrained=false인 smoke 모델이고 기존 validation mAP도 0이다. RGB만 입력, conf≥0.25, IoU 0.45, class 0, 선택 bbox 1.5배 조건에서 **검출 0/27, detector→PnP 0/27, 명시적 대칭 성공 0/27**이다. 실패 전체를 분모에 포함했다. 검출 실패 시 pose는 실행되지 않았고 GT 기반 ROI로 대체하지 않았다. 이는 해당 미성숙 체크포인트의 결과이지 YOLO 일반 성능이 아니다. `detector_eval.csv`, `overlays/detector/`에 실패를 남겼다. 입력에는 GT bbox·mask·pose를 주지 않았다.

## BB100 보정·누출 감사 및 inference-only

RAW 428프레임이 있는 `qwen_smt/data/BB_rgb_obj04/run_20260813_164421`에서 100장과 시간·로봇 mapping을 찾았다. BB scene K는 개발27 K와 수치상 동일하다. BB에 적용된 D의 독립 출처와 기존 영상의 생성 기록은 확인되지 않아, 개발27 K,D를 가정하고 output K=원 K, 1280×720, crop/resize 없이 `bb100_undistorted_K_original/`에 새 PNG 100장을 만들었다. 기존 보정 JPG와 채널당 평균 절대 차이 0.510/255, 프레임별 최대 평균 0.659/255로 같은 보정과 압축에 부합하나 동일한 calibration 이력의 증명은 아니다. 원본 SHA-256과 기존 평가 입력 85개의 기존 해시는 재확인 시 일치했다(검사 범위 외 파일 전수 불변 증명 아님).

BB 원본과 개발27 원본 사이 완전 동일 SHA-256은 0쌍이다. 이것은 유사 장면·연속 구간·재인코딩 중복이 없다는 뜻이 아니다. BB 100장은 하나의 기록된 촬영 세션에 속하고 기존 조사에서 수치상 서로 다른 pose 36개다. 시간 1초 이내 **또는** 평행이동 5 mm 이내 및 회전 5° 이내를 연결한 탐색적 전이 그룹은 {'31': 36, '221': 64}장이다. `bb100_audit.csv`에는 그룹, 시간, 로봇 step, 상태 {'FEEDING': 1, 'READY': 11, 'APPROACHING': 11, 'PICKING': 14, 'TRANSPORTING': 22, 'PLACING': 14, 'RETURNING': 27}, mapping validity {'1': 100}, 해시, 가장 가까운 개발 이미지·pose 후보가 기록돼 있다. 로봇 step은 기록했으나 독립 주기 구분을 검증하지 못했다. 시간·pose 임계값은 가설이며 두 그룹은 같은 세션이므로 독립 세션으로 취급하지 않는다. 개발27과 세션 관계도 확정하지 못했다.

대표 10개 CAD 투영은 `overlays/bb100_projection/`. 육안 검사한 043에서는 주요 외곽과 구멍이 대체로 겹치지만 미세 정합 오차를 정량화하지 않았고, 235에서는 그리퍼가 투영 영역을 가린다. 이 amodal 투영은 visible mask가 아니다. 전 프레임 CAD vertex가 화면 앞/안에 있다는 산술 검사와 pose JSON/NPY 일치는 실제 GT 정확도 검증이 아니다. 대표 10장 모두에 대한 사람의 정밀 정합 판정은 아직 미완료다.

새 보정 영상을 사용한 공식 checkpoint **BB100 추론 전용** 진단은 GT 투영 oracle ROI 조건에서 PnP 100/100, ADD 0/100, ADD-S 78/100, 명시적 대칭 ADD 55/100이다. `bb100_pose_diagnostic.csv`, `bb100_inference/`에 프레임별 결과와 overlay/mask/XYZ를 저장했다. D 출처와 pose 정확도, 독립성이 불확실해 이 결과는 조건부 개발 진단이다. 양호한 점수라도 세션 일반화나 실제 detector 성능을 증명하지 않는다. 이 100장은 학습하지 않았다.

## 세 학습 방식 판단

- **A 공식 그대로: 조건부 GO.** 통제된 oracle 개발 평가 기준으로 사용한다. 무검출 환경에서 실서비스 GO는 아니다.
- **B PBR 추가 fine-tuning: 현재 NO-GO.** 원본 `HccePose/bop_loader.py`의 `pnp_solve_re_4p`, `modified_sym_Rt`는 e_rot 기준으로 대칭을 선택하고 `R Rs`, `R ts+t`를 반영한다. 기존 PBR XYZ 생성은 대칭 canonicalization을 반영하지 않아 공식 가중치와 다른 목표가 될 수 있다. 새 데이터 생성 파이프라인은 구현·검증하지 않았다. 공식 학습 PBR과의 중복 및 독립 평가 부재가 해소되고, 공식 renderer/depth/e_rot까지 공식 코드와 픽셀·pose 수준 일치 검증한 뒤에만 별도 파일럿을 추진한다. 현재 이미 공식 성능이 높고 학습 이득을 판단할 기준도 없어 잘못된 라벨로 파일럿을 시작하지 않았다.
- **C BB 실사 적응: 지도 학습 NO-GO.** 기존 `bb_weak_supervision_20261108` 실사 gate는 검증된 가림 추정이 없어 0이고 SAM 후보도 GT가 아니다. CAD amodal이나 SAM 전체를 양성/XYZ 정답으로 사용하지 않았다. Pose 기반 렌더 일관성은 가림·보정·pose 오류와 대칭 분기가 혼합되고, RGB 일관성은 그리퍼·반사·조명 때문에 신뢰 gate 없이 그라디언트가 잘못될 수 있다. 교사-학생 변환 일관성이나 renderer 기반 손실은 별도 구현 및 신뢰성 검증이 필요하다. 학습하지 않았다.

## 지연 시간

RTX 5090, batch 1, 이미 undistort된 개발 프레임 26을 반복, warm-up 5회 후 30회 GPU 동기화 측정. 단위 ms. 전처리는 crop·정규화·H2D이며 파일 읽기와 undistortion 제외, pose total은 detector 제외다.

| 구간 | 평균 | 중앙값 | p95 |
|---|---:|---:|---:|
| rgb_preprocess_crop_normalize_h2d | 0.405 | 0.398 | 0.414 |
| hcce_network_forward | 7.159 | 7.165 | 7.196 |
| hcce_decode_and_gpu_to_cpu | 0.965 | 0.964 | 0.976 |
| pnp_cpu | 6.787 | 6.785 | 6.814 |
| pose_total | 15.315 | 15.314 | 15.358 |
| detector_predict | 3.265 | 3.252 | 3.342 |

검출 0/30이므로 실제 detector→pose end-to-end 지연·FPS는 측정하지 못했다. 단일 프레임 반복 수치이며 목표 FPS 미정이다. pose 공식 모델 peak allocated 약 396 MiB, reserved 500 MiB(개발27 재현); BB 진단 allocated 약 396 MiB, reserved 496 MiB. 장치 전체 메모리와는 다르다.

지연 측정 초기 코드에서 HCCE bit dtype을 float32로 강제해 기존 FP16 decode와 동일성 검사가 실패했다. 기존 dtype 유지로 수정하고 원래 inference 출력과 일치시켰다. 이후 첫 정상 계산 출력 중 list에 round를 적용해 출력 부분에서 예외가 났고, 계산 JSON은 `latency_attempt_print_error.json`으로 보존한 뒤 출력 수정·재측정했다. 모델 및 과거 결과는 수정하지 않았다.

## 실행한 것과 남은 검증

실행: 재현, ROI 351회, detector 27장, BB 100장의 보정 및 추론 진단, latency. 미실행: detector/pose 학습, PBR 재평가, 대칭 canonical XYZ 생성 파이프라인, BB visible GT/검증된 confidence 생성, 독립 세션 평가, 실시간 전체 경로 측정. GPU 학습은 실행하지 않았다.

재현용 스크립트는 산출물 덮어쓰기를 거부한다. 먼저 새 빈 디렉터리로 복사하고 기존 별도 환경을 사용한다. 전체 재실행은 GPU·시간을 사용하므로 필요할 때만 실행한다. 다음은 쉘 예시(기존 결과 경로는 읽기 전용):

```bash
TASK_SRC=/RESEARCH_DATA/HCCEPose_experiments/official_rgb_pose_advanced_20261108
TASK_NEW=/RESEARCH_DATA/HCCEPose_experiments/official_rgb_pose_advanced_reproduction_$(date +%Y%m%d_%H%M%S)
mkdir "$TASK_NEW"
cp "$TASK_SRC"/*.py "$TASK_NEW"/
TASK_PY="$TASK_SRC/.detector_env/bin/python"
"$TASK_PY" -B "$TASK_NEW/reproduce.py"
"$TASK_PY" -B "$TASK_NEW/roi_robustness.py"
"$TASK_PY" -B "$TASK_NEW/detector_eval.py"
"$TASK_PY" -B "$TASK_NEW/bb_audit.py"
"$TASK_PY" -B "$TASK_NEW/bb100_diagnostic.py"
"$TASK_PY" -B "$TASK_NEW/latency.py"
```

이 실행은 기존 absolute-path 데이터와 환경 의존성이 있다. 동일 버전 및 파일 해시/설정은 `experiment_manifest.json`을 참조한다. 컴퓨팅 GPU가 사용 중일 때는 스크립트가 중단된다. 다음 우선순위는 `next_experiments.md` 참조.
