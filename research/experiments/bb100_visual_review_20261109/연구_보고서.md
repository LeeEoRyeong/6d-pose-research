# BB100 GT 시각 검수 준비 보고서

2026-11-09. 100개 비교 패널과 검수 인덱스를 준비했다. **사람 검수 전 상태는 100장 모두 UNREVIEWED이며 학습 상태는 HOLD다.** 검수 UI의 ACCEPT 역시 시각 검수 기록일 뿐 자동으로 학습 승인을 의미하지 않는다. 기존 GT·원본·모델은 수정하지 않았고 학습하지 않았다.

## 카메라와 좌표계

사용자가 BB100과 기존 C_rgb_obj04를 **동일한 Tapo 카메라로 촬영했다고 확인**했다. 이는 사용자 진술이며 별도의 장치 식별 측정이 아니다. 사용자가 제공한 Windows 보정값 1280×720, fx=984.70009004, fy=983.75715611, cx=635.41416344, cy=362.61850196, D=[−0.28801442, −0.07604108, −0.00069984, 0.00055886, 0.12258375]는 서버의 개발27 `camera_params.json` 값과 일치한다. newK=K, `cv2.undistort(img,K,D,None,K)`도 사용자 제공 처리 이력이다.

추가로 로컬 RAW 후보 JPEG 100장에 이 **직접 `cv2.undistort`**를 적용해 JPEG q95로 저장한 결과, 기존 라벨 JPEG와 디코딩된 픽셀 및 JPEG 바이트가 **100/100 모두 일치**했다. 이전 Phase 11의 `initUndistortRectifyMap` + `remap` 경로는 평균 MAE 약 0.00218/255였으나, 직접 `cv2.undistort`의 수치 경로가 이 라벨 JPEG와는 완전히 일치했다. `camera_check.json`에는 100장별 결과가 있다. 이는 주어진 입력에서 출력 파일을 정확히 재현한 증거이며, 과거 실행 로그·카메라의 모든 촬영 설정·실제 pose 정확도를 독립 인증하지는 않는다. RAW 후보는 카메라가 저장한 JPEG로 Bayer RAW라고 가정하지 않는다.

각 이미지의 라벨 NPY pose는 BOP R,t와 일치하며, CAD obj04 SHA-256은 공식 모델과 같다. 좌표는 `X_camera = R X_model + t`, 원래 K로 이미 보정된 라벨 영상에 zero distortion으로 투영했다. 기존 Phase 10 amodal 윤곽을 재사용하고 model origin과 +X/+Y/+Z 방향 50 CAD 단위 축을 추가했다. 화면에는 X 빨강, Y 초록, Z 파랑, 투영 bbox 청록, CAD amodal 윤곽 노랑이다. BOP CAD 단위는 mm이나 실사 pose의 물리적 정밀도는 별도 확인이 필요하다.

## 검수 자료

- `index.html`: 브라우저에서 여는 로컬 검수 인덱스. P1/P2·검수 상태·프레임/pose 그룹 필터, 프레임별 상태/가림/반사/경계/흐림·메모 기록 및 CSV 다운로드를 제공한다.
- `comparisons/000xxx.jpg`: 100장 각각의 **라벨 원본 영상, 기존 GT 후보 CAD 투영, 동일 좌표 확대 비교**. 라벨 원본은 이미 보정된 작업용 JPEG이며 새 보정을 적용하지 않았다. 프레임 가장자리 crop은 비율을 유지한다.
- `review_template.csv`: 각 프레임 UNREVIEWED, 시각 속성 UNKNOWN, 학습 HOLD로 초기화한 사람 작성용 표. `p1_priority.csv`: 우선순위 P1 45장. `pose_groups.csv`: 동일 R,t 36그룹의 전체 목록.

Phase 10에서 043·235를 예비 관찰한 기록은 있으나, 독립 사람 검수가 완료된 상태는 아니므로 이번 검수표에서 자동으로 ACCEPT하거나 가림 상태를 확정하지 않았다. 모든 상태는 사용자가 직접 정한다. P1은 기존 복사 이력·동일 pose 재사용 가능성·모델 진단 불일치 등을 이용한 **검수 순서**다. 모델 진단은 GT 오류의 증거가 아니다.

031, 032, 034, 036, 038, 040, 042, 043, 044, 045, 046, 054, 057, 060, 063, 067, 071, 074, 075, 077, 079, 081, 083, 085, 087, 089, 090, 099, 101, 103, 105, 107, 109, 336, 338, 358, 359, 367, 371, 388, 420, 422, 424, 427, 428

먼저 **043과 060**은 043→060 pose 복사 이력이 있으므로 두 영상 각각의 윤곽과 구멍 위치, 동일한 축 방향 및 가림 상태를 비교한다. 같은 수치의 pose가 반드시 틀렸다는 뜻은 아니다. 이후 031·075(서로 다른 상태에서 동일 pose), 032–042·044–074 등 반복 그룹, 336·338·359·367·371·388·420–428을 확인한다. 전체 정확한 그룹 구성과 촬영 순서는 `pose_groups.csv`에 있다. 동일 pose라고 개별 영상의 검수를 건너뛰지 않는다.

## 사람이 프레임마다 확인할 항목

1. 왼쪽 원본 확대와 오른쪽 후보 투영의 **외곽, 모서리, 평면 경계, 원형 구멍** 위치가 함께 맞는지 본다. 위치가 비슷해도 깊이·회전이 정밀하게 맞는다는 독립 인증은 아니다.
2. 빨강 X·초록 Y·파랑 Z 축 방향과 물체의 실제 방향이 합리적인지 확인한다. 물체 대칭으로 축 표현이 달라 보일 수 있으므로 대칭 정의를 함께 살핀다.
3. 그리퍼·호스에 실제로 가려진 부분은 `occlusion`에 별도 기록한다. CAD 윤곽은 가림 뒤까지 포함하는 amodal 투영이며 가려진 영역을 visible GT로 취급하지 않는다.
4. 반사로 경계가 달라 보이는지, 흐림이 있는지, 물체와 배경 경계가 구분되는지 각각 `reflection`, `blur`, `boundary`에 기록한다. 단정할 수 없으면 UNKNOWN/UNCERTAIN으로 둔다.
5. 시각적으로 수용 가능하면 ACCEPT, 재라벨링이 필요하면 CORRECT, 판단이 어렵다면 UNCERTAIN을 선택한다. 검수자·시각·이유를 기록한다. 기존 pose를 이 UI에서 수정하지 않는다.

상태 선택은 브라우저 localStorage에만 남는다. 브라우저/오리진이 바뀌거나 데이터가 지워질 수 있으므로 반드시 **CSV 내보내기**로 별도 파일을 저장한다. 모든 내보낸 행의 `training_status`는 상태 선택과 무관하게 HOLD다. 입력한 CSV는 원본 연구 데이터나 `review_template.csv`를 덮어쓰지 않는다.

## 독립성·실행 제한

이 100장은 같은 촬영 세션에 속한다. 동일·근접 pose와 인접 시간 연결 그룹이 36/64장이라는 기존 누출 검토를 유지하며, 이 그룹 분리는 독립적인 촬영 세션 검증을 대체하지 않는다. ACCEPT 여부만으로 학습·검증 분할이나 fine-tuning을 시작하지 않는다. 보정 타깃·GT pose 정밀도 및 필요한 별도 촬영 조건의 확인은 남아 있다.

100개 비교 이미지, 45개 P1 목록 및 36개 pose 그룹을 생성했고, 이미지·pose·Phase 10 overlay·K 등 주요 307개 원본 입력의 SHA-256이 생성 전후 일치했다. 전체 저장소의 모든 파일에 대한 검사는 아니다. 첫 비교 패널 버전에서 화면 가장자리 5장의 crop이 정사각형으로 늘어나도록 만들어졌음을 발견해 `attempt_stretched/`에 보존한 뒤 비율 유지 방식으로 다시 생성했다. 이 보존본은 검수에 사용하지 않는다.

검수 JavaScript는 모의 DOM에서 100개 카드·P1 45개 필터·상태 저장·HOLD가 유지되는 CSV 내보내기를 확인했다. 실제 브라우저별 호환성은 이 서버에서 확인하지 못했다. 실행 방법은 `사용법.md`, 생성 코드는 `generate.py`와 `check_camera.py`다.
