# PBR + BB 약한 감독 구현 및 CPU smoke 결과

작성일 2026-11-08. 판정 **GPU 본 학습 NO-GO**. 기존 데이터·코드·PBR 분할·baseline checkpoint를 수정하지 않았고, BB 100장 전체 렌더링이나 GPU 학습을 실행하지 않았다.

## 구현

- `pipeline.BBAdapter`는 BB RGB·K·pose·CAD 및 기존 `generate_xyz_v2.py` CPU 렌더러를 읽어 CAD amodal support 및 front/back XYZ를 계산한다. 원본의 `pad_square_fp32`, `crop_square_resize`, `hcce_encode`를 사용한다. 동일한 pose의 허용 그룹 내부에서 번호 차이 20 이내인 가장 가까운 참조를 찾으며, 참조가 있을 때 RGB 차이는 **진단용**으로만 출력한다. 참조 후보의 split을 호출자가 제한해야 한다.
- `UnknownOcclusionEstimator`는 신뢰할 수 있는 실사 가림 분할 모델이 없어서 `U_front`, `U_back`, `Q+`, `Q-`를 모두 0으로 반환한다. RGB 차이로 가림 픽셀·confidence를 확정하지 않는다. CAD mask를 visible GT로 사용하지 않는다. 안정적인 자동 가림 추정과 C의 저가림 선택은 **미구현**이다.
- `weak_loss.total_loss`는 PBR에 기존 `network_model_explicit.py`의 `HccePose_Loss`를 그대로 호출한다. 실사 mask/XYZ loss는 분리된 명시적 gate에만 적용하며, gate 바깥은 gradient 0이다. PBR에서만 동적 weight/history를 갱신하고 실사에는 그 결과를 detach해 사용한다. 빈 gate는 NaN 없이 loss 0이다. 초기 실사 계수 0.25는 검증 전 가설이다.
- `training.mixed_step`은 PBR 3 + real 1 구성의 **CPU 단일 step**을 지원한다. `pipeline.balanced_ids`는 이미 분리된 pose 그룹의 균등 sampling을 지원한다. 실제 전체 훈련 루프, B/C selector, checkpoint selector와 GPU 학습은 미구현이며, 기본적으로 빈 실사 gate는 step 시작 전 NO-GO 오류를 낸다. Smoke만 별도 옵션으로 빈 gate를 허용해 백엔드 흐름을 검사했다.

## 선택 결과

메타데이터만 사용한 `inventory.py`에서 BB 100장 중 이 구현의 신뢰 감독 대상은 **0장**이며 저가림으로 선택된 C 프레임도 0장이다. 이는 가림이 100장 모두 심하다는 측정 결과가 아니라 **가림 신뢰도를 추정하는 검증된 모델이 없어서 전부 보류한 정책 결과**다. BB 100장의 실제 가림률이나 잠재적 사용 가능 비율은 미측정이다. 프레임별 동일-pose 후보와 사유: [frame_selection.csv](runs/inventory_20261108T134529_89f4cb4d/frame_selection.csv).

실제 렌더링한 네 장은 모두 U/Q가 0픽셀이고 CAD 대비 유효 비율 0%다. 이는 네 장의 물체가 안 보인다는 뜻이 아니다.

## 검증 결과

1. Synthetic tensor: gate 밖 실사 front/back 및 mask logits의 gradient가 정확히 0이고, 빈 gate loss는 유한한 0이다. 양성/음성 gate는 해당 위치에서만 gradient를 만든다.
2. 기존 PBR criterion 단독과 새 PBR 경로는 세 차례 호출에서 loss 값, 입력 gradient와 동적 weight/history가 bitwise 일치했다. 실사 약한 loss 계산은 PBR history를 갱신하지 않았다. 이는 loss 함수 테스트이며 혼합 batch의 BatchNorm 통계가 PBR-only batch와 같다는 뜻은 아니다.
3. 기존 HCCE encode/decode는 X/Y/Z 각각 0–255의 모든 값에 대해 round-trip이 일치했다. RGB 256, mask/XYZ 128 crop, bbox pad1.5와 nearest gate crop을 확인했다.
4. BB 043/075/235/247에서 CAD depth front≤back, bbox, K·pose 데이터 대응 및 5개 독립 ray 교차를 확인했다. 043의 amodal/front/back은 이전 예비 결과와 픽셀 단위로 일치했다. PBR train 0/10의 front/back은 기존 저장 라벨과 모두 픽셀 일치했다. 이 일치는 같은 CPU 렌더러 경로를 기준으로 하며 VisPy 독립 bitwise 일치를 증명하지 않는다.
5. 실제 HCCEPose 모델로 CPU에서 3 PBR + 1 BB forward/backward 및 optimizer 1 step을 실행했다. 총 loss/PBR loss는 3.5340083, 실사 mask/XYZ loss는 각각 0이었다. 실사 감독 성능이 검증됐다는 뜻은 아니다. GPU는 초기화하지 않았다.
6. 사용한 RGB·pose·PBR 라벨, CAD, baseline checkpoint·split·네트워크 코드 등 22개 파일은 smoke 전후 SHA-256이 같았다. 검사 범위는 이 22개이며 전체 저장소의 모든 파일을 해시한 것은 아니다.

## 남은 작업과 Go/No-Go

- 신뢰 가능한 자동 실사 가림 추정기/분할 모델과 실제 영상의 독립 검증 근거를 확보해 confidence 및 ignore 정책을 정해야 한다. 기존 10장의 CAD 투영은 실사 visible GT가 아니다. 무작위 confidence 또는 erosion만으로 내부 그리퍼 가림을 감지했다고 주장하지 않는다.
- 동일/근접 pose 및 시간·촬영 주기로 train/evaluation 누출 여부를 확정하고, estimator 입력/reference도 같은 split에서만 가져오도록 구성해야 한다. 지금 inventory의 후보는 평가 split이 정해지지 않았으므로 학습 참조 목록으로 바로 사용하면 안 된다.
- 실제 real gate가 양수인 사례에서 좌표·mask gradient, 경계·가림 제외, 점유율 및 PBR 성능 보존을 검증해야 한다. 실사 모델의 실패율을 뒷받침할 독립 신뢰 데이터가 없으면 안전한 gate를 입증할 수 없다.
- B/C 전용 분할·학습/검증·checkpoint 선택·평가 루프는 아직 없다. 구현과 통제 후 기존 baseline과 같은 PBR val20 및 제한이 명시된 실사 개발27의 oracle ROI 평가가 필요하다.

이 조건들을 만족하기 전에는 GPU 본 학습을 시작하지 않는다.
